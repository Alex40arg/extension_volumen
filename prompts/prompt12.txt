Lee completamente `DEVELOPMENT_SPEC.md`, `README.md` y revisa la versión actual del proyecto antes de modificar nada.

La extensión actual funciona correctamente para:

* control de volumen por pestaña;
* ecualizador;
* presets;
* spectrum analyzer;
* múltiples pestañas;
* procesamiento local.

Sin embargo, detectamos una limitación importante:

Cuando `Audio Processing` está ON y la pestaña está siendo procesada mediante `chrome.tabCapture`, sitios como YouTube y Dailymotion no pueden entrar en fullscreen HTML5 real mediante el botón del reproductor.

Sí funciona:

* fullscreen cuando la extensión está OFF;
* F11 del navegador.

Esto coincide con la limitación conocida de Chromium relacionada con self-capture y `requestFullscreen()`.

Quiero implementar una **prueba experimental controlada** de una arquitectura alternativa que permita mantener fullscreen nativo cuando sea posible.

NO reemplaces todavía el sistema actual de `tabCapture`.

# 8. HTMLMediaElement

Para cada elemento `video` o `audio` apropiado:

usar conceptualmente:

```javascript
audioContext.createMediaElementSource(mediaElement)
```

y conectar a la cadena DSP.

Evitar conectar el mismo elemento más de una vez.

Mantener un registro por elemento procesado.

---

# 9. Elementos multimedia dinámicos

Sitios como YouTube pueden reemplazar o recrear elementos durante navegación SPA.

El modo experimental debe manejar razonablemente:

* cambio de video;
* navegación interna;
* reemplazo del `<video>`;
* aparición tardía de elementos.

Puede utilizarse `MutationObserver` si es necesario.

Evitar observación excesivamente agresiva.

---

 ↓

 ↓

 ↓

 ↓

 ↓

* mismo comportamiento de mute;
* mismo master volume;
* mismo smoothing.

No introducir diferencias audibles innecesarias entre backends.

# 11. Fullscreen

El objetivo central es:

Con backend in-page activo:

* YouTube debe poder entrar en fullscreen real;
* Dailymotion debe poder entrar en fullscreen real;
* Chrome UI debe desaparecer como normalmente;
* no debe requerirse F11.

No interceptar ni modificar `requestFullscreen()`.

La solución debe permitir que la página use su fullscreen nativo.

---

# 12. Audio original

Al conectar un `HTMLMediaElement` con `createMediaElementSource`, evita audio duplicado.

Debe existir una única ruta audible.

No permitir:

```text
audio original
+
audio procesado
```

simultáneamente.

---

# 13. CORS / DRM / restricciones

Ten en cuenta que algunos sitios pueden impedir o limitar procesamiento con `MediaElementAudioSourceNode`, especialmente por:

* CORS;
* DRM;
* media protegida;
* implementación interna del sitio.

En esos casos:

* no romper reproducción;
* detectar fallo;
* limpiar cualquier estado parcial;
* permitir fallback a `tabCapture`.

---

# 14. Fallback automático

Diseñar una estrategia clara:

```text
Intentar in-page
    ↓
si funciona
    → usar in-page
si falla
    → usar tabCapture
```

No mezclar ambos backends simultáneamente sobre la misma pestaña.

Nunca procesar dos veces el mismo audio.

# 21. Desactivación

Al apagar Audio Processing:

si backend = in-page:

* desconectar nodos;
* restaurar reproducción normal;
* cerrar AudioContext si corresponde;
* dejar el `<video>/<audio>` funcionando normalmente;
* liberar observers/listeners.

si backend = tabCapture:

* mantener cleanup actual.

---

# 22. Cambio de pestaña

Mantener independencia completa entre pestañas.

Una pestaña puede usar:

```text
in-page
```

y otra:

```text
tab-capture
```

simultáneamente.

---

# 23. Evitar conflictos

No permitir:

* dos AudioContexts procesando el mismo media element;
* dos backends activos simultáneamente en una pestaña;
* doble conexión de `MediaElementSource`;
* audio duplicado;
* sesiones zombie.

---

# 24. Popup cerrado

Cerrar el popup no debe detener el procesamiento.

El modo in-page debe continuar funcionando mientras la pestaña exista y Audio Processing esté ON.
