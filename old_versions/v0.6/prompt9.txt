# 2. Spectrum Analyzer

Agregar un analizador de espectro usando Web Audio API.

Usar:

```text
AnalyserNode
```

No usar datos simulados.

No generar animaciones falsas.

El analizador debe representar realmente el audio capturado de la pestaña.

---

# 3. Posición en la cadena DSP

Insertar el analizador después del ecualizador y antes del master volume.

Cadena conceptual:

```text
Source
 ↓
EQ
 ↓
AnalyserNode
 ↓
Master Gain
 ↓
Destination
```

Motivo:

El analizador debe mostrar el contenido tonal resultante del EQ, pero no debe reducir visualmente su amplitud simplemente porque el usuario bajó el master volume.

Mantener esta posición salvo que exista una razón técnica fuerte para cambiarla.

---

# 4. El AnalyserNode no debe alterar el sonido

El `AnalyserNode` debe actuar como nodo de análisis, no como efecto audible.

No debe:

* cambiar gain;
* cambiar respuesta tonal;
* generar latencia perceptible;
* modificar dinámica.

EQ OFF + Analyzer ON debe sonar igual que EQ OFF + Analyzer OFF.

---

# 5. Toggle independiente

Agregar:

```text
Spectrum Analyzer   ON / OFF
```

Default:

```text
OFF
```

El analizador no debe activarse automáticamente al instalar la extensión.

El usuario debe decidir si quiere visualizarlo.

---

# 6. Comportamiento cuando Audio Processing está OFF

Si `Audio Processing` está OFF:

* el analizador no puede mostrar audio real;
* debe quedar visualmente inactivo;
* no debe ejecutar loop gráfico;
* no debe consumir CPU innecesariamente.

Puede conservarse temporalmente la preferencia ON/OFF durante la vida de la pestaña si resulta coherente con el modelo actual.

Pero nunca debe iniciar captura por sí mismo.

---

# 7. Comportamiento al reactivar Audio Processing

Si el usuario tenía:

```text
Analyzer ON
```

y apaga Audio Processing:

* detener renderizado;
* destruir sesión DSP normalmente;
* conservar la preferencia temporal si corresponde.

Al volver a activar Audio Processing:

* Volume = 100%;
* Mute = OFF;
* EQ recupera estado actual;
* Analyzer puede volver ON si estaba ON antes.

No amplificar volumen automáticamente.

---

# 8. Estado por pestaña

El estado del analizador debe ser independiente por pestaña.

Ejemplo:

```text
Tab A:
Analyzer ON

Tab B:
Analyzer OFF

Tab C:
Analyzer ON
```

No propagar estado entre tabs.

No persistir por hostname.

No guardar automáticamente en `chrome.storage.local` salvo que ya exista un mecanismo explícito para settings de pestaña.

---

# 9. Configuración inicial del AnalyserNode

Usar valores razonables.

Propuesta inicial:

```text
fftSize = 2048
```

Puede usarse:

```text
1024
```

si ofrece una mejor relación entre suavidad y rendimiento.

Configurar también:

```text
smoothingTimeConstant
```

con un valor moderado, aproximadamente:

```text
0.7 – 0.85
```

El objetivo es que el gráfico:

* responda;
* no tiemble excesivamente;
* se vea fluido;
* no parezca pegado o lento.

Documenta en código los valores elegidos.

---

# 15. Distribución de frecuencias

El eje horizontal debe representar frecuencias de forma musical.

Preferir distribución:

```text
logarítmica
```

en lugar de lineal pura.

Esto es importante para dar espacio visual razonable a graves, medios y agudos.

No mostrar cientos de bins directamente uno a uno.

Agrupar bins en un número razonable de barras.

Rango visual aproximado:

```text
30 Hz → 15 kHz
```

Puede extenderse ligeramente si simplifica la implementación.

---

# 16. Número de barras

Usar una cantidad razonable, por ejemplo:

```text
32
48
64
```

Elige según tamaño del canvas.

Evitar:

* demasiadas barras diminutas;
* pocas barras enormes.

Debe verse fluido y útil.

---

# 17. Labels de frecuencia

# 18. Escala vertical


# 19. Loop de renderizado

Usar:

```text
requestAnimationFrame
```

solo mientras:

* Audio Processing está ON;
* Analyzer está ON;
* popup está abierto.

IMPORTANTE:

El popup desaparece al cerrarse, por lo tanto el loop gráfico no debe seguir existiendo fuera de él.

El DSP puede mantener el AnalyserNode, pero la visualización solo debe ejecutarse mientras el popup exista.

---

# 20. Comunicación de datos

Diseña una forma eficiente de obtener datos del analizador.

Evita enviar grandes arrays a través de `chrome.runtime.sendMessage` 60 veces por segundo si existe una alternativa más eficiente.

Prioriza:

1. estabilidad;
2. bajo consumo;
3. simplicidad;
4. arquitectura clara.

Si el popup necesita recibir datos desde el offscreen document mediante mensajería, limita el frame rate si es necesario.

Por ejemplo:

```text
20–30 FPS
```

puede ser suficiente visualmente.

No es obligatorio alcanzar 60 FPS.

---

# 21. Rendimiento

El analizador debe ser ligero.

Evitar:

* loops excesivos;
* allocation de arrays grandes cada frame;
* creación continua de nodos;
* mensajes innecesarios;
* redibujado si está OFF.

Reutilizar buffers.

---

# 22. Analyzer OFF

Cuando se apaga el Analyzer:

* detener inmediatamente loop visual;
* limpiar canvas o mostrar estado inactivo;
* no destruir EQ ni volumen;
* no alterar audio.

Puede mantenerse el AnalyserNode dentro de la cadena si eso simplifica el DSP y no consume significativamente.

---

# 23. Cleanup

Cuando la pestaña se cierra o Audio Processing se apaga:

* limpiar referencias del analyser;
* detener cualquier polling asociado;
* mantener cleanup idempotente;
* no afectar otras pestañas.

# 40. Pruebas manuales/lógicas

## A. Analyzer OFF

Audio Processing ON.

Analyzer OFF.

Confirmar:

* audio normal;
* sin gráfico activo;
* sin errores.

---

## B. Analyzer ON

Activar Analyzer.

Debe aparecer espectro dinámico real.

---

## C. EQ

Mover:

```text
30 Hz +8
```

El analizador debe reflejar aumento relativo de graves si el audio contiene esas frecuencias.

---

## D. EQ Flat

Volver Flat.

La respuesta visual debe regresar coherentemente.

---

## E. Master volume

Mover:

```text
100% → 30%
```

El espectro no debe colapsar proporcionalmente simplemente por bajar master volume, ya que está antes del GainNode.

---

## F. Mute

Mute puede silenciar salida.

El analizador puede continuar mostrando señal pre-master mientras exista audio capturado.

Este comportamiento es aceptable y debe documentarse.

---

## G. Analyzer OFF/ON repetido

Alternar varias veces.

No debe:

* crear nodos duplicados;
* acelerar animación;
* generar errores.

---

## H. Popup close

Analyzer ON.

Cerrar popup.

Reabrir.

No deben existir loops gráficos huérfanos.

---

## I. Dos pestañas

Tab A Analyzer ON.

Tab B Analyzer OFF.

Estados independientes.

---

## J. Save preset

Seleccionar Soft V.

Sin tocar faders:

```text
Save disabled
```

Mover una banda:

```text
Custom
Save enabled
```

Guardar.

```text
Save disabled
```

---

## K. Text selection

Arrastrar mouse sobre títulos y labels.

No deben seleccionarse.

Editar nombre de preset.

El texto dentro del input sí debe poder seleccionarse.
